## Decision (confirmed with the human)

Canonical agent format stays the Claude Code list form (`tools: Read, Grep, ...`)
that `agents/*.md` already use. There is no format both tools recognize
natively — verified live (Claude Code 2.1.228, OpenCode 1.18.16): OpenCode
hard-errors on list-form `tools:` ("Expected object | undefined, got ..."),
and Claude Code silently does NOT enforce map-form `tools:` (a
`tools: {read: true}` agent could still run Bash), which would quietly break
the read-only agents' restriction under Claude. Claude also requires a `name:`
frontmatter key that OpenCode's native format does not have.

So the pipeline that converts is unavoidable in the OpenCode direction, and it
already exists at Docker build time for the built-in agents (awk strips
`name:`/`tools:`). The missing half of the brief: custom project agents in
`docs/agents/` are mounted verbatim to both tools with no conversion. This job
routes them through the same conversion at launch time (host-side Go, OpenCode
sessions only). Claude Code sessions are untouched — the list form is its
native schema and `docs/agents/` already works there via the docs mount.

Out of scope (confirmed): rewriting the built-ins to map form, and the OpenCode
`permission:` enforcement follow-up documented in README (the
"unrestricted under OpenCode" caveat stays uniform for built-in and custom
agents — conversion strips `tools:` rather than converting to a map).
