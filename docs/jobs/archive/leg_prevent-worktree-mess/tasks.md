## Context — the two questions in the brief

**Q1 — Can we deny agents the ability to prune/remove worktrees?**

Today: no effective denial exists.

- Claude Code runs with `--dangerously-skip-permissions`
  (`scripts/entrypoint.sh`), so every bash command is auto-approved and the
  `permission:` frontmatter blocks in `agents/*.md` — an OpenCode-only schema —
  are ignored entirely.
- OpenCode runs with `--auto`; its `permission:` blocks do apply, but the
  `developer` agent has no block at all (full bash), and the read-only agents'
  allowlists still permit `git branch *` (which matches `git branch -D
  <branch>`) plus `git add`/`git commit` (`agents/reviewer.md`,
  `agents/security.md`).
- Every session mounts the job worktree at `/workspace` (rw) and the repo's
  git common dir (rw), so `git worktree remove`, `git worktree prune`,
  `git branch -D`, and direct `rm -rf` on git metadata are all reachable.

The fix is layered: a container-side git shim (TASK-1), per-agent read-only
gitdir mounts (TASK-2), tightened OpenCode permission blocks (TASK-3), and
read-only overlay mounts inside the gitdir mount (TASK-4/TASK-5). TASK-1 is
the primary defense for the committing agents (whose gitdir must stay
writable); TASK-2 is the hard filesystem boundary for the non-committing
agents; TASK-4/TASK-5 shrink the blast radius of the gitdir mount itself.

**Q2 — Is this especially stupid because of how worktrees are saved and
mounted?**

Yes. A job's worktree is a *linked* worktree: the working tree lives under
`<dirname(project)>/.manigot-worktrees/<basename(project)>/<id>_<slug>/` (or
nested under the project root on a mount point), and its `.git` is a pointer
file into the main repo's git dir — the worktree-specific gitdir is
`<GitCommonDir>/worktrees/<id>_<slug>/`. For git to work inside the container,
the session launcher bind-mounts the whole git common dir at its host path
read-write (`-v <GitCommonDir>:<GitCommonDir>:z`, `internal/session/docker.go`
lines 209-212, set from `Root.GitCommonDir` in `internal/session/root.go` line
140).

That single mount exposes the ENTIRE repository's git metadata to every agent,
including the read-only ones:

- every branch ref (`refs/heads/*`, incl. `main` and all other jobs' branches),
- `.git/config`, `hooks/`, `objects/`, `logs/`, `info/`, `packed-refs`,
- the main worktree's `HEAD` and `index` (which live in the common dir, not
  under `worktrees/`),
- and — because job worktrees are registered under
  `<GitCommonDir>/worktrees/<id>_<slug>/` — every other job's worktree gitdir.

The sibling `.manigot-worktrees/` working trees are not mounted (partial
containment), but their gitdirs are. So a misbehaving agent can, with rw
access: delete another job's worktree registration (producing exactly the
"orphaned worktree" mess `job.DiscoverOrphans` exists to clean up), `git
branch -D` any branch, rewrite `.git/config`, corrupt the main worktree's
index/HEAD, or plant a `hooks/` script that would execute on later host-side
git operations (`mg done`, `mg delete`) with host privileges. The blast radius
is the whole repository, not the one job the agent was given.

Known limitation (deliberate, out of scope): `mg host` sessions run the agent
CLI directly on the host with no container isolation — none of TASK-1/2/4/5
apply there, matching the documented "host sessions have no isolation" design.

## Task breakdown

TASK-1: Add a container-side `git` shim (generated by `scripts/entrypoint.sh`)
that allowlists read + commit git subcommands and refuses everything else
(`worktree`, `branch -d/-D`, `reset`, `clean`, `gc`, `prune`, `reflog`,
`push`, `fetch`, `pull`, `checkout`, `switch`, `restore`, `stash`, `remote`,
`update-ref`, `tag` writes, `merge`, `rebase`, ...) with a clear message, so
agents under both CLIs can "read the git log and make commits" and nothing
more.
     files: scripts/entrypoint.sh; doc sync: docs/AGENTS.md, agents/*.md,
            project-template/docs/AGENTS.md
     depends: none
     risk: medium — an over-tight allowlist can break legitimate agent git
           flows (reviewer's `git diff <base>...HEAD`, developer's
           `git add -A`), the shim must parse leading `git -C <dir>` style
           options, must exec the real git by absolute path (no recursion),
           and must be installed after the entrypoint's own `git config
           --global` calls; it is a soft layer (a determined agent can call
           `/usr/bin/git` directly or write the mounted gitdir) — the hard
           boundary for non-committing agents is TASK-2.

TASK-2: Give non-committing agents a read-only git-common-dir mount: add an
explicit `commit:` frontmatter marker to `agents/*.md` (only `developer` and
`reviewer` — reviewer commits `verdict.md` — get `commit: true`), have the
session launcher read the resolved agent's file (global via `home.Root()`,
project override via `docs/agents/`, default rw when absent/unknown so no
committing agent ever breaks) and mount `Root.GitCommonDir` with `:ro` +
`GIT_OPTIONAL_LOCKS=0` for non-committing agents instead of `:z`.
     files: internal/session/docker.go, internal/session/root.go (or new
            internal/session/agentgit.go), internal/session/docker_test.go,
            agents/developer.md, agents/reviewer.md, internal/session/
            agentconv.go + agentconv_test.go (verify `commit:` passes the
            OpenCode strip untouched); doc sync: docs/AGENTS.md,
            project-template/docs/AGENTS.md
     depends: none (pairs with TASK-1; both are "deny" layers, land in either
              order)
     risk: high — misclassifying an agent that actually commits (or a project
           override that does) yields confusing git errors; read commands that
           refresh the index (`git status`/`git diff`) need
           GIT_OPTIONAL_LOCKS=0 on a ro gitdir; docker argv tests pin the `:z`
           suffix; agent-file resolution must mirror agentlist's
           global-vs-project override logic.

TASK-3: Tighten the OpenCode `permission:` bash allowlists in the read-only
agents (drop the broad `git branch *` allow that matches `git branch -D`, and
deny-first `git worktree*`, `git branch -d*`/`-D*`, `git reset*`, `git clean*`,
`git gc*`, `git prune*`, `git reflog*`, `git push*`, `git fetch*`, `git pull*`,
`git checkout*`, `git switch*`, `git restore*`, `git stash*`, `git remote*`,
`git tag -d*`, `git update-ref*`), and add a matching `permission:` block to
`agents/developer.md` (currently unrestricted under OpenCode) that allows its
normal edit/bash work but denies the destructive git set.
     files: agents/analyst.md, agents/reviewer.md, agents/security.md,
            agents/developer.md, internal/session/agentconv_test.go; doc
            sync: docs/AGENTS.md, project-template/docs/AGENTS.md
     depends: none
     risk: low — OpenCode-only (Claude Code ignores these blocks; TASK-1
           covers Claude), but the exact prefix-matching semantics of the
           installed opencode version must be verified so the allows still
           match the read commands the agents actually run.

TASK-4: Add a read-only overlay mount for `<GitCommonDir>/hooks` (mounted
after the gitdir mount itself, `:ro`, skipping when the source does not exist)
in job-worktree sessions, so an agent cannot plant a hook that would later
execute on host-side git operations with host privileges.
     files: internal/session/docker.go, internal/session/docker_test.go
     depends: none (composes with both the rw and ro gitdir mounts of TASK-2;
              land after TASK-2 to keep the mount-construction diff reviewable)
     risk: medium — nested docker bind-mount semantics (a subpath mount
           shadows the parent; the source must exist or docker creates an
           empty root-owned dir), and git must still read/execute hooks on a
           ro mount (it can — ro preserves read+execute).

TASK-5: Add read-only overlay mounts for every OTHER job's worktree gitdir
(`<GitCommonDir>/worktrees/<name>`, skipping the current job's — it must stay
rw for commits — and skipping missing sources) in job-worktree sessions, so a
misbehaving agent cannot delete or corrupt another job's worktree
registration; requires a new `internal/git` helper that enumerates worktree
gitdirs via `git worktree list --porcelain` (extending the parsing already in
`git.WorktreeForBranch`).
     files: internal/session/docker.go, internal/git/git.go (new helper, e.g.
            WorktreeGitDirs), internal/git/git_test.go or new worktree test,
            internal/session/docker_test.go
     depends: TASK-4 (shares the nested-overlay construction pattern in
              docker.go)
     risk: high — a new git invocation in the session hot path, the gitdir
           enumeration can go stale mid-session (a job created during a
           session is out of scope — note it), missing sources must be
           skipped (docker would create them as dirs), and argv-pinning tests
           need updating.
