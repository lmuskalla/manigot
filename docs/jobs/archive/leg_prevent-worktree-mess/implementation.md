# Implementation: prevent worktree mess

id: leg
status: open
developer: developer
date: 2026-08-13

## Summary

Implemented the four-layer defense against agents pruning/removing worktrees
or otherwise messing with the repository's git metadata:

1. A container-side `git` shim (`scripts/entrypoint.sh`) that allowlists read +
   commit git subcommands and refuses everything else, under both CLIs.
2. A read-only git-common-dir mount for non-committing agents, driven by a new
   `commit:` frontmatter marker in `agents/*.md`.
3. Tightened OpenCode `permission:` bash blocks (dropped the broad
   `git branch *` allow) and added a matching block to `developer`.
4. Read-only overlay mounts inside the gitdir mount shadowing `<GitCommonDir>/hooks`
   and every other job's worktree gitdir, so a misbehaving agent cannot plant a
   hook or corrupt/delete another job's worktree registration.

Answer to the brief's Q2 ("is this especially stupid because of how worktrees
are saved and mounted?"): yes — the single rw git-common-dir mount exposed the
entire repo's git metadata (all branch refs, config, hooks, main-worktree
HEAD/index, and every other job's worktree gitdir) to every agent. TASK-2
shrinks it to read-only for the agents that don't commit, and TASK-4/TASK-5
shrink the blast radius of the mount itself for the ones that must keep it
writable.

## Changes

TASK-1: added a PATH-first `git` shim generated by `scripts/entrypoint.sh`
(installed after the entrypoint's own `git config --global` calls). It parses
leading `git -C <dir>`-style global options, allowlists the read + commit
subcommands (`add`, `commit`, `log`, `diff`, `show`, `status`, `rev-parse`,
read-only `branch`/`config`, plumbing reads, ...), refuses `worktree`,
`branch -d/-D`, `reset`, `clean`, `gc`, `prune`, `reflog`, `push`, `fetch`,
`pull`, `checkout`, `switch`, `restore`, `stash`, `remote`, `tag` writes,
`update-ref`, `merge`, `rebase`, ... with a clear message, and execs the real
git by absolute path (no recursion). It is a soft layer; the hard boundary for
non-committing agents is TASK-2. Doc sync: `docs/AGENTS.md` (new "Session git
shim" section + `scripts/entrypoint.sh`/`internal/session` bullets),
`agents/developer.md` + `agents/reviewer.md` (git-restriction note),
`project-template/docs/AGENTS.md`.

TASK-2: added a `commit:` frontmatter marker to every agent — `commit: true`
for `developer`, `reviewer` (reviewer commits `verdict.md`), and `quality`
(quality commits its review note to `quality.md`), `commit: false` for the
eight read-only agents. New `internal/session/agentgit.go` resolves the
active agent's file (project `docs/agents/` override wins over the global
`agents/` file, mirroring `agentlist`; absent/unknown/missing defaults to
committing so no committing agent ever breaks) and reads the marker.
`BuildDockerInvocation` mounts `Root.GitCommonDir` `:ro` +
`-e GIT_OPTIONAL_LOCKS=0` for non-committing agents instead of `:z` (the lock
flag is required because read commands like `git status`/`git diff` refresh the
index). Tests: docker argv pins for ro/rw/override/unknown cases;
`agentconv_test.go` verifies `commit:` passes the OpenCode strip untouched.
Doc sync: `docs/AGENTS.md` ("Read-only git mount for non-committing agents"),
`project-template/docs/AGENTS.md`.

TASK-3: tightened the OpenCode `permission:` bash blocks in `agents/reviewer.md`
and `agents/security.md` — dropped the broad `git branch *` allow (which
matched `git branch -D <branch>`) and the bare `git branch` allow, replaced them
with a specific `git branch --show-current` allow, and added explicit denies
for the destructive git set (`worktree`, `branch -d/-D`, `reset`, `clean`,
`gc`, `prune`, `reflog`, `push`, `fetch`, `pull`, `checkout`, `switch`,
`restore`, `stash`, `remote`, `tag -d`, `update-ref`). Added a matching
`permission:` block to `agents/developer.md` (previously unrestricted under
OpenCode): `"*": allow` base with the same denies after it. Denies are listed
after the allows because OpenCode evaluates permission rules last-match-wins
(verified against the v1.18.18 docs). `analyst.md` already had `bash: deny` —
no change. Doc sync: `docs/AGENTS.md`, `project-template/docs/AGENTS.md`;
`agentconv_test.go` now exercises deny-rule passthrough.

TASK-4: job-worktree sessions now get a read-only overlay mount for
`<GitCommonDir>/hooks` (mounted after the gitdir mount, `:ro`, skipped when
the source is missing) so an agent cannot plant a hook that would later execute
on host-side git operations (`mg done`, `mg delete`) with host privileges.
Tests: hooks mount present when the dir exists, absent when removed, and plain
(non-job) sessions carry no overlays. Doc sync: `docs/AGENTS.md`.

TASK-5: new `internal/git` helper `WorktreeGitDirs(root, currentPath)` that
enumerates every linked worktree's gitdir via `git worktree list --porcelain`
(extending the parsing in `WorktreeForBranch`) plus a per-worktree
`git rev-parse --git-dir`, excluding the caller's own worktree and the main
worktree's common dir, and skipping unresolvable/prunable entries. The session
launcher mounts every other job's worktree gitdir (`<GitCommonDir>/worktrees/<name>`)
`:ro`, skipping missing sources, so a misbehaving agent cannot delete or
corrupt another job's worktree registration; the current job's gitdir stays
writable for commits. The enumeration runs once at launch — a job created
mid-session is not covered until the next launch (noted in `docs/AGENTS.md`).
Tests: helper exclusions/prunable/not-a-repo + docker argv overlay pins.

## Follow-up fixes (review round 2)

- Blocker: `agents/quality.md` was marked `commit: false`, but its own
  instructions require it to run `git add quality.md` + `git commit` — with
  the read-only git-common-dir mount that commit would physically fail,
  leaving `quality.md` uncommitted and blocking `mg done`. Fixed by marking
  quality `commit: true` (it commits its review note exactly like reviewer
  commits `verdict.md`); doc sync in `docs/AGENTS.md` and
  `internal/session/agentgit.go`.
- Blocker: `project-template/docs/AGENTS.md` claimed "everything else defaults
  to a read-only git mount", contradicting the implementation (default is
  writable when no agent is named, the file is missing, or the marker is
  absent/unknown) and the main `docs/AGENTS.md`. Fixed the template to
  describe the writable default and the explicit `commit: false` opt-in for a
  read-only mount.
- Non-blocking verification: the installed opencode binary (v1.18.18)
  accepts the unknown `commit:` frontmatter key — live-verified by adding a
  test agent carrying `commit: true` + a `permission:` block to a scratch
  project and running `opencode agent list` (agent parsed and listed, no
  hard error, permission block passed through). Cleaned up afterwards.

## Known issues / follow-ups

- `mg host` sessions run the agent CLI directly on the host with no container
  isolation — none of the shim/ro-mount/overlay layers apply there, matching
  the documented "host sessions have no isolation" design (deliberate, noted
  in the task breakdown).
- The git shim is a soft layer: a determined agent can exec the real git at its
  absolute path (`/usr/bin/git`) or write the mounted gitdir. For committing
  agents (whose gitdir must stay writable) that residual exposure is accepted;
  TASK-4/TASK-5 shrink its blast radius to the current job's own gitdir.
- The worktree-gitdir overlay list is captured once at session launch and can
  go stale mid-session (a job created during a session is not covered until the
  next launch) — the list cannot be refreshed from inside the container.
- OpenCode permission semantics (last matching rule wins) were verified against
  the v1.18.18 docs; the `commit:` key acceptance was live-verified with the
  installed binary via `opencode agent list` (see follow-up fixes above).
  Live behavior against a provider was not exercised in this environment.
- The git shim allows `git branch <name>` (branch creation, a ref write) —
  only the destructive forms (`-d/-D/-m/-M/-c/-C/-f/--delete*`/...) are denied.
  Harmless for the worktree-protection goal; flagged as a non-blocking
  "consider" by review.
